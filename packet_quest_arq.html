Understanding Stop-and-Wait ARQ

S

Sender (Customer)

The customer places an order online. In networking terms, this is the sender transmitting a data packet. Only one order is sent at a time, waiting for confirmation before proceeding.

R

Receiver (Amazon Server)

Amazon's server receives the order and processes it. In networking, this is the receiver that accepts data packets and sends back acknowledgments (ACKs).

A

ACK (Order Confirmation)

The confirmation message sent back to customer. This acknowledgment tells the sender that the packet was received successfully and it's safe to send the next one.

N

Noisy Channel

Network interference that can cause packet loss. Like internet connectivity issues, this represents real-world communication challenges requiring retransmission mechanisms.

How Stop-and-Wait ARQ Works:

  1. Send: Sender transmits one frame (order request) with sequence number (0 or 1) and starts a timer
  2. Wait: Sender waits for acknowledgment (order confirmation) from receiver
  3. Receive ACK: If correct ACK arrives before timeout, toggle sequence number and send next frame
  4. Timeout: If no ACK arrives in time, retransmit the same frame with same sequence number
  5. Duplicate Detection: Receiver checks sequence number to detect and discard duplicate packets
  6. Error Handling: Lost packets or ACKs trigger automatic retransmission with same sequence number

Key concepts

Timeout period: The sender waits for a specific duration. If no ACK is received within this time, it assumes the packet or ACK was lost and retransmits.

1-bit sequence numbers: Each packet uses alternating sequence number (0, 1, 0, 1...) to distinguish between new packets and retransmissions. This is the minimal sequence numbering for Stop-and-Wait ARQ.

Duplicate detection: Receiver maintains expected sequence number. If received packet's sequence number doesn't match, it's a duplicate and gets discarded (but ACK is still sent).

Reliability: The protocol guarantees delivery by retransmitting until correct acknowledgment is received.

Efficiency trade-off: While reliable, the protocol sacrifices speed for guaranteed delivery.

Conclusion: Stop & Wait ARQ with 1-Bit Sequence Numbering

Advantages

  • Simple implementation and easy to understand
  • Guaranteed reliable data delivery with duplicate detection
  • Minimal overhead - only 1 bit needed for sequence number
  • Low memory requirements (only one frame buffered)
  • Excellent error detection and correction

Limitations

  • Low throughput and inefficient bandwidth usage
  • Significant idle time while waiting for ACK
  • Not suitable for high-speed, long-distance networks
  • Performance degrades with increased propagation delay
  • Channel underutilization - only one packet in transit
